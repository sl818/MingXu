## 四、分阶段改动明细

### 4.1 布局体系（三布局 + 导航统一）

**新增函数（4 个）**：`quickAddModal`、`heroWeekPanel`、`railWeekHtml`、`railRemindHtml`

**改写的原有函数**：`viewToday`、`viewBoard`、`viewCalendar`、`viewStats`、`viewHabits`、`viewWeight`、`viewSettings`、`render`、`refreshAutoTheme`

**做了什么**

- 在原有 `top`（顶部导航）/ `side`（左侧导航）之外新增 `wide`（宽屏三栏：左导航 228px + 主区 + 右栏）
- 导航顺序统一为：今日 / 用药 / 待办 / 随笔 / 体重 / 习惯 / 日历 / 统计 / 设置
- 宽屏 `[data-layout="top"]` 且视口 ≥1520px 时 `#main` 最大宽度 1200 → 1680
- 手机端改 D 方案：底部 4 tab（今日/用药/待办/设置）+ 中间悬浮 ＋（54px 圆钮，`margin-top:-20px` 上浮），其余页面收进设置页「更多页面」
- 深绿 Hero 恢复并适配三种布局：日期行 + 标题 + 副标题 + chips，右侧本周战报（大字均值 + 7 天柱），再右侧完成度圆环

**关键设计约束**：所有布局差异都通过 `:root[data-layout="..."]` 作用域限定，不污染其它布局；宽屏压缩样式全部包在 `@media(min-width:701px)` 内，避免手机上圆环溢出（这个坑踩过一次）。

### 4.2 用药管理（改动量最大的一块）

**需求演进**：删「服药时间」→ 改「每日次数 + 每次时间 + 饭前饭后」→ 加「饭前/后多久」→ 加「厂商 + 药品信息备注」→ 卡片从两列到折叠到单条到轮播 → 新增独立用药页 → 加统计卡

**新增函数（13 个）**：`cnCount`、`mealLabelOf`、`offsetText`、`mealTimingText`、`medDayText`、`defaultSlots`、`timeSlotsHtml`、`medPhaseOf`、`medMealRank`、`medSortFn`、`medShortName`、`medRowHtml`、`viewMeds`

**删除函数**：`medManageRows`（被独立用药页取代）

**改写的原有函数**：`medFormModal`、`bindMedForm`、`saveMedForm`、`viewToday`、`isPrn`、`medCard`、`medSheetHtml`、`refreshMedSheet`

**做了什么**

1. **药品数据模型扩展**（`med` 对象新增字段）：`courseType`（long/short/prn）、`mealTiming`（before/after/with/empty）、`mealOffset`（0/10/15/…/自定义）、`manufacturer`、`medInfo`；`times` 从单值变数组（1–6 次）
2. **用药面板重构**：次数下拉（1–6）动态生成时间槽；饭前后选择联动「间隔时长」；选「按需」时整组时间字段隐藏
3. **今日用药卡**：≥2 种药 → 叠层轮播（药名条简称 + 两侧箭头 + `1/4` 指示 + 固定 `min-height:88px` 防跳动）；=1 种 → 单条 + 胶囊可直接打卡；=0 → 「添加用药」
4. **独立用药页**：四板块（进行中/未开始/暂停中/已停用），每行主信息「每天 N 次，每次 X 单位 + 餐前半小时」深色加粗，次要信息（用途/厂商/规格/疗程）浅灰
5. **排序规则**：餐前 → 随餐 → 空腹 → 餐后 → 未设置，同档按首个时间，再按名称（`MED_MEAL_RANK`）
6. **统计卡 6 张**（v24）：药品总数 / 进行中（含未开始副行）/ 已暂停 / 已停用 / 今日服药（带进度条）/ 库存告急（≤7 天，暖色）

**一个容易忽略的实现细节**：轮播的当前索引 `medCardIdx` 是**模块级变量，不进 `state`**，否则翻一张卡就会触发一次云端保存。实测翻卡云保存次数 0。

| `med` | `courseType`、`mealTiming`、`mealOffset`、`manufacturer`、`medInfo`；`times` 变数组 | 不需，缺字段按默认值渲染 |
| `weight` / `bodyProfile` | 无 | 无 |
| `checks` / `events` / `doses` | 无（结构未动） | 无 |

**没有删除任何已有字段，没有改字段语义**。这是"历史数据零迁移"的基础。
