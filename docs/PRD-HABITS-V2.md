## 二、背景与目标

### 2.1 现状（已核对代码，非推测）

| 现有能力  | 实现方式                                                                 | 局限                                             |
| ----- | -------------------------------------------------------------------- | ---------------------------------------------- |
| 习惯类型  | `type`：`build` 养成 / `quit` 戒除 / `smoke` 戒烟                           | 只能表达「每天做」或「每天不犯」                               |
| 目标量   | `target`（1–99）+ `unit`                                               | 语义固定为**每天** N 次/单位，无法表达每周、每月、每 N 天             |
| 应打卡判定 | `habitDueOn()` 复用**通知频率** `notifyFreq`（daily/weekly/monthly + 星期/日号） | 「每周只提醒一次」被迫等于「每周只该做一次」。想做「每周 3 次、只在周日晚提醒」表达不出来 |
| 达标判定  | `met(h,d)` 按天二元判定                                                    | 周一到周三没做，日判定已经算失败；但「本周 3 次」在周四仍可达成              |
| 日完成度  | `habitDayAcc()`，仅用于月度小结                                              | 只有日粒度，没有周期粒度                                   |
| 时段    | `deadline`（仅「保持 × 单次目标」可用）                                           | 只有一个截止点，没有「早/中/晚」分段，没有时间窗                      |
| 戒除    | 默认守住，点一次记一次失守（单次/多次）                                                 | 没有「每周允许 N 次」的额度概念，偶尔一次等于全盘失败                   |

**一句话结论**：现有模型是「一天一格」的模型，而用户想记录的是「一段时间内的节奏」。这不是字段不够，而是**评价单位选错了**。

### 2.2 要解决的问题

| 编号 | 问题         | 后果                                            |
| -- | ---------- | --------------------------------------------- |
| P1 | 低频习惯被每天要求  | 一周 3 次健身被设成每日目标 → 达标率虚低（周均 43%），连续天数天天断，正反馈消失 |
| P2 | 应打卡被通知频率绑架 | 想减少打扰就得谎报频率；真实节奏无处表达                          |
| P3 | 一天内的时段无法表达 | 「早中晚各一杯水」「睡前 1 小时内不看手机」只能靠备注，无法判定             |
| P4 | 缺弹性机制      | 出差、生病、忙到深夜 = 直接断连；断一次就放弃是习惯类工具最大的流失点          |
| P5 | 戒除只有黑白     | 「每周最多 2 次奶茶」这种控量目标无法记录，只能记成「每天都失守」或「完全不记」     |

### 2.3 目标与成功指标

| 指标         | 口径（定义 / 时间范围 / 排除项）                                             | 现状基线                         | 目标                  |
| ---------- | --------------------------------------------------------------- | ---------------------------- | ------------------- |
| M1 表达能力覆盖率 | 用户想执行的习惯中，能用界面配置准确表达的比例；统计口径为「新建/编辑后自评 + 抽查 20 条配置」；排除仅存备注无法判定的 | 5/7 ≈ 71%（每周 3 次、每月 1 次无法表达） | 100%                |
| M2 应打卡误判率  | 今日页「待办」中出现、但当天实际非应做的习惯条数 ÷ 出现总条数；按自然日统计                         | 无法量化（现有模型不产生该问题）             | 0                   |
| M3 口径自洽率   | 同一习惯在「今日页 / 日历热力 / 月报」三处显示的达标结论一致的比例；抽查最近 30 天                  | 100%（因只有日口径）                 | 保持 100%             |
| M4 打卡摩擦    | ①新建习惯从点击到保存的中位耗时；②单次打卡的点击数（含撤销）                                 | 新建约 45s / 打卡 1 次             | 新建 ≤ 60s / 打卡 ≤ 2 次 |
| M5 零回归     | 常驻卡相关字段与渲染的变更量（`optional=false` 及 `PINNED_IDS` 路径）              | —                            | **0 变更**            |

> 本项目为单人工具，不使用 DAU/留存类指标。M1、M3、M5 是硬指标，M2、M4 是体验指标。

### 2.4 非目标

- 不追求「功能数量对齐商业 App」；每个新增配置项都必须回答「没有它，哪种真实习惯表达不出来」。
- 不做社交、组队、排行榜、付费墙。

## 三、名词与术语定义

| 术语           | 定义                                                                  | 与现有字段的关系                             |
| ------------ | ------------------------------------------------------------------- | ------------------------------------ |
| 节奏（Sched）    | 一个习惯「多久来一次」的规则，取值：每天 / 指定星期 / 每周 N 次 / 每 N 天 / 每月 N 次 / 每月某日 / 限期挑战 | 新建 `sched`；不再复用 `notifyFreq`         |
| 配额（Quota）    | 一个周期内要达成的量，含计量类型（次数/数值）、目标值、单位、比较方向（≥/≤）                            | 复用 `target`、`unit` 作为兼容映射，新增 `quota` |
| 周期（Period）   | 判定达标的时间单位：日 / 周（周一至周日，可配置）/ 月 / N 天滚动段                              | 新增派生概念，不存字段                          |
| 计划日          | 用户「打算做」的日子（指定星期、每月某日）                                               | 新增，与「完成日」分离                          |
| 完成日          | 实际产生打卡记录的日子                                                         | 现有 `checks` / `events`               |
| 弹性出现         | 配额型习惯：本周期未达成前天天出现在待办，达成后当天起折叠                                       | 新增展示策略 `policy.appear`               |
| 日达标          | 当天完成度是否满足**当日**要求（日型习惯的唯一判定）                                        | 现有 `met(h,d)` 语义收窄                   |
| 周期达标         | 本周期累计完成度是否满足配额                                                      | 新增 `metPeriod()`                     |
| 贡献度          | 某天的打卡量对本周期进度的贡献（0–1 或具体数值）                                          | 扩展 `habitDayAcc()`                   |
| 时段（Slot）     | 一天内划分的时间段，含名称与起止时刻（如 早 06:00–09:00）                                 | 新增 `slots`，与 `deadline` 并存           |
| 跳过（Skip）     | 本周期内主动放弃一次，不计失败，有次数上限                                               | 新增，落在 `events` 的 `k='skip'`          |
| 补卡（Backfill） | 事后补记最近 N 天内的记录                                                      | 新增，记录带 `backfilled:true`             |
| 暂停（Pause）    | 一段时间内不做、不出现在待办、不计入统计、不断连续                                           | 新增 `policy.pausedFrom/To`            |
| 宽限           | 周期结束后仍允许补记的天数（本期仅对周/月型开放，默认 0）                                      | 新增                                   |

## 四、需求范围

### 4.1 本期包含

1. 七种节奏：每天、指定星期、每周 N 次、每 N 天、每月 N 次、每月某日、限期挑战（起止日期）。
2. 配额与计量：次数型、数值型（含单位与 ≥/≤），支持「每次多少」与「每周期多少」两种口径。
3. 时段拆分：一天内 2–4 个时段，各时段独立配额；与截止时刻并存。
4. 展示策略：弹性出现 / 固定计划日。
5. 弹性机制：补卡（默认近 7 天）、跳过（默认每周 1 次）、暂停、休息日。
6. 判定与统计：双层口径（日达标 / 周期达标）、周期进度、连续周期数。
7. 界面：今日小习惯区重构、新建/编辑三步表单、习惯详情周期视图、管理列表周期徽标。
8. 兼容：老习惯零改动映射；常驻卡完全不读新字段。

### 4.2 本期不做（明确排除）

| 不做项                                                      | 原因                             | 去向           |
| -------------------------------------------------------- | ------------------------------ | ------------ |
| 常驻卡（`optional=false` / `PINNED_IDS` / 戒烟 / 用药）的任何逻辑与样式改动 | 用户明确要求，且常驻区是多处统计与提醒的依赖         | 永久不做         |
| 通知系统改造（推送时段、免打扰、频道）                                      | 用户明确交由现有通知系统，本期不改              | 不涉及          |
| 计时器型打卡（正计时/倒计时）                                          | 计时状态涉及多端同步与后台挂起，收益可用「数值型-分钟」覆盖 | v2 评估        |
| 递减目标（戒烟逐月减量）                                             | 需求真实但属独立模型，避免本期范围蔓延            | v2 评估        |
| 弹性分（指数平滑评分）                                              | 算法需调参与解释成本，先做周期连续              | v2 评估        |
| 社交/组队/共享习惯                                               | 单人工具，无需求                       | 不做           |
| 习惯模板市场                                                   | 用「预设模板」轻量替代（见 FR-10）           | 本期只做 6 个内置预设 |

## 五、方案对比与选型说明

### 5.1 同品类通用做法（设计输入，非抄袭）

> 以下为公开资料中可核对的通用交互模式归纳，用于论证取舍；不复制任何产品的文案、视觉与专有内容。

| 产品                 | 频率模型                                                                     | 量化                  | 弹性/其他                             | 可借鉴点                                  |
| ------------------ | ------------------------------------------------------------------------ | ------------------- | --------------------------------- | ------------------------------------- |
| Loop Habit Tracker | 是/否型：每天、每 N 天、每周 X 天、每周或每月 X 次、每 X 天做 Y 天；量化型：单位 + 目标值 + 日/周/月 + 「至少/至多」 | 支持「≥ 目标」与「≤ 目标」两种方向 | 日历用斜纹表示「不需要做」；评分用指数平滑，断一天不清零；支持跳过 | **「至少/至多」双方向**、**未计划日显式区分**、**周期内配额** |
| TickTick 习惯        | 每天（可选星期几）／每周（选次数）                                                        | 「达到某个量」目标           | 可给过去任意日期补打卡；多条提醒                  | **计划日与完成日分离**、**补卡**                  |
| Streaks            | 每日 + 每周若干次                                                               | 计数型、计时型             | 负向习惯（戒除）单独建模                      | **养成/戒除分层建模**                         |
| 国内同类（小日常、习惯打卡类）    | 每天／每周 X 次／自定义                                                            | 次数为主                | 时段分组（早/中/晚）、打卡日历                  | **时段分组**贴合中文用户心智                      |

**归纳出的四条共识**：

1. 频率一定包含「每天 / 每周 N 天 / 每周 N 次 / 每 N 天」四类，缺一不可；
2. 量化必须有单位与比较方向，否则「少喝」类目标无法表达；
3. 「今天不需要做」必须显式可见（斜纹/灰格），否则用户会误以为漏打卡；
4. 补卡与跳过是留存关键，不是高级功能。

**本站可差异化的两点**（商业 App 普遍不做或做得重）：

- 周期与提醒彻底解耦（本站提醒是自有系统，天然可解耦）；
- 周期视图与「今日待办」同屏，不做二级页面跳转。

### 5.2 候选方案

| 维度       | 方案 A：给 `met()` 加分支                                       | 方案 B：周期一等公民 + 双层判定                                                           | 方案 C：习惯模块整体重写                 |
| -------- | -------------------------------------------------------- | ---------------------------------------------------------------------------- | ----------------------------- |
| 思路       | 在现有 `met(h,d)` 里按 `type` 加 if；`habitDueOn` 换一个字段读        | 新增 `sched`/`quota`/`slots`/`policy`；判定拆成 `dueOn`、`met`、`metPeriod` 三层；统计按层取数 | 习惯独立成 store 与视图层，与现有 state 解耦 |
| 实现成本     | 低                                                        | 中                                                                            | 高                             |
| 对现有统计的影响 | **高**：`met` 被日历、连续天数、月报、`dayStats` 共用，加分支会出现「同一习惯三处结论不同」 | 可控：`met` 语义收窄、周期型走新函数，改动面可枚举                                                 | 需重建全部统计                       |
| 表达能力     | 中（能配出来，但口径会自相矛盾）                                         | 完整                                                                           | 完整                            |
| 风险       | 高（静默错数，最难排查）                                             | 中（口径需一次性对齐）                                                                  | 高（多端快照合并、导入导出、SW 缓存全受影响）      |
| 上线时间     | 快                                                        | 中                                                                            | 慢                             |
| 综合评价     | 不推荐                                                      | **推荐**                                                                       | 本期不做                          |

### 5.3 推荐结论

**采用方案 B**。理由：

1. 本站的核心资产是「一份全量快照 + 多端合并」，任何会污染 `met()` 的改动都会以静默错数的方式扩散到 6 个以上视图，排查成本远高于一次性把判定分层。
2. 周期型习惯的判定天然是「一段时间结束后才知道」，与「当天就知道」是两种语义，**必须两个函数**，不能一个函数两个分支。
3. 方案 B 的改动面可枚举：新增字段只在非常驻习惯上生效，常驻卡继续走旧路径，回归边界清晰。

### 5.4 演进路径

| 阶段     | 内容                                    | 触发条件                           |
| ------ | ------------------------------------- | ------------------------------ |
| 本期（P0） | 周期模型 + 配额 + 时段 + 双层口径 + 表单 + 今日区 + 迁移 | 无（本次交付）                        |
| P1     | 详情周期视图、补卡、跳过、暂停、休息日                   | P0 上线满 2 周且 M3 口径自洽率 100%      |

## 六、用户角色与使用场景

### 6.1 角色

| 角色                    | 描述                         | 关键诉求                         |
| --------------------- | -------------------------- | ---------------------------- |
| 陛下（唯一用户，PC 为主 + 手机查看） | 自建自用的生活记录者，已有 7 个习惯、5 张常驻卡 | 想记录真实节奏；不想被工具评判；不想每天面对 7 条全红 |
| 多端（同一账号第二台设备）         | 手机端只做快速打卡                  | 打卡即时同步，不产生重复记录               |

### 6.2 核心场景（用户故事）

**US-1 每周三次健身**

> 作为用户，我想把「健身」设成每周 3 次，以便不被「每天都该练」绑架。
>
> - Given 习惯「健身」节奏=每周 3 次、配额=1 次、弹性出现
> - When 我在周一完成 1 次
> - Then 卡片显示「本周 1/3 · 还差 2 次 · 还剩 5 天」，今日列表继续保留该习惯（未达配额）

**US-2 每三天浇花**

> - Given 节奏=每 3 天（锚点 11-01）
> - When 今天是 11-04
> - Then 该习惯出现在今日待办并标「今天该做」；11-05 不出现在待办，且日历格显示斜纹而非空白

**US-3 早中晚三杯水**

> - Given 节奏=每天、配额=3 杯、时段=早/中/晚 各 1 杯
> - When 我在 08:10 点了一次
> - Then 「早」时段胶囊变实心并显示 08:10，「今日 1/3」；若 09:00 后补，仍计入但标「晚于时段」

**US-4 每周最多两杯奶茶（戒除额度）**

> - Given 类型=戒除、配额=每周 ≤2 次
> - When 本周第 3 次点击「又喝了一次」
> - Then 本周状态从「额度内」变「已超额」，连续周数归零，卡片不显示「连续 N 天」而显示「本周 3/2」

**US-5 出差暂停**

> - Given 习惯处于暂停区间 11-10 至 11-14
> - When 11-12 打开今日页
> - Then 该习惯不出现在待办；11-15 恢复后连续周期数不因暂停中断

### 6.3 场景地图（关键触点）

感知（今日页看到「本周还差 2 次」）→ 执行（一次点击）→ 反馈（进度环 + 还差 N 次文案）→ 周期结算（周日晚显示「本周达成 3/3」）→ 复盘（详情页周/月视图）→ 调整（改节奏，历史不回算）

## 七、功能需求

> 编号规则：FR-xx；每条含描述、业务规则、Given/When/Then 验收标准。状态词统一：**必须（shall）／应该（should）／可以（may）／禁止（must not）**。

### FR-01 节奏规则（Sched）

**描述**：习惯必须拥有且仅拥有一种节奏，七选一。

| 取值           | 参数                                 | 语义                   | 周期单位        | 示例        |
| ------------ | ---------------------------------- | -------------------- | ----------- | --------- |
| `daily`      | —                                  | 每天都要                 | 日           | 喝水        |
| `weekdays`   | `days[]`（0–6，0=周日）                 | 只在指定星期要做             | 日（未命中日=不需要） | 周一三五跑步    |
| `weekly`     | `perWeek`（1–7）                     | 每自然周内任意 N 天达成        | 周           | 每周健身 3 次  |
| `interval`   | `intervalDays`（1–60）+ `anchorDate` | 每 N 天一个周期段           | N 天滚动段      | 每 3 天浇花   |
| `monthly`    | `perMonth`（1–31）                   | 每自然月内任意 N 天达成        | 月           | 每月理发 1 次  |
| `monthlyDay` | `monthDay`（1–31，月末收敛）              | 每月固定某日要做             | 月           | 每月 1 号记账  |
| `once`       | `startDate` + `endDate`            | 限期挑战，区间内按 `daily` 判定 | 日           | 连续 21 天冥想 |

**业务规则**：

- R1.1 周期起点：周以**周一**为首日（`weekStart=1`）；若后续开放配置，取值 0–6，全部周期计算必须读同一配置。
- R1.2 `interval` 必须使用固定锚点分段（`floor((d - anchorDate) / N)`），**禁止**用「上次完成日」推算，否则拖延会导致周期无限后移。
- R1.3 `monthlyDay` 若当月无该日（如 31 号遇 2 月），收敛到当月最后一天，并在界面提示「2 月为 28 日」。
- R1.4 节奏与通知频率**必须完全解耦**：`sched` 决定「该不该做」，`notifyFreq` 只决定「什么时候提醒」。二者不得互相推导。
- R1.5 节奏变更只影响**当前未结算周期及未来**，已结算周期按快照保留（见 FR-13）。

**验收标准**

- Given 节奏=`weekly`、`perWeek=3`，When 查看任意周三，Then 该习惯出现在今日待办（弹性策略下）且进度显示「本周 x/3」。
- Given 节奏=`weekdays`、`days=[1,3,5]`，When 查看周二，Then 该习惯**不**出现在今日待办，日历格显示「不需要」样式（斜纹），不显示为空白。
- Given 节奏=`interval`、`intervalDays=3`、`anchorDate=2026-11-01`，When 今天为 2026-11-07，Then 判定为第 3 段（11-07 至 11-09）的第 1 天，标记「今天该做」。
- Given `perWeek=3`，When 用户在周四修改为 `perWeek=5`，Then 本周剩余判定按 5 次计算，但历史周不做回算，且界面提示「本周目标已调整」。

### FR-02 配额与计量（Quota）

**描述**：周期内的目标量与计量方式。

| 字段        | 取值                | 说明                    |
| --------- | ----------------- | --------------------- |
| `kind`    | `count` / `value` | 次数型（点一次 +1）／数值型（录入数值） |
| `target`  | 1–9999（次数型 1–99）  | 目标值                   |
| `unit`    | ≤4 字              | 次/杯/ml/页/km/分钟/支      |
| `cmp`     | `gte` / `lte`     | ≥（养成型默认）／≤（戒除与控量型默认）  |
| `perSlot` | 布尔                | 配额是「每周期总量」还是「每时段各一份」  |

**业务规则**：

- R2.1 养成型（`build`）默认 `cmp=gte`；戒除型（`quit`）默认 `cmp=lte`，且 `target` 表示**期间允许的上限次数**，「0 次」等价于现有「每天都守住」。
- R2.2 数值型必须带单位；数值精度上限 1 位小数，范围 0–99999，禁止负数。
- R2.3 次数型 `target=1` 等价布尔；界面不显示「1/1」，只显示「已完成」。
- R2.4 `perSlot=true` 时，周期配额 = 各时段配额之和；某时段未达标，当日不算完全达标，但**不否定**本周期已累计的量（见 FR-09 口径）。
- R2.5 单位变更不得改写历史记录数值；历史单位按打卡当时的 `unit` 快照显示。

**验收标准**

- Given 配额 kind=`value`、target=2000、unit=ml、cmp=`gte`，When 录入 1500，Then 进度 75%、状态「进行中」，不判定达标。
- Given 戒除型、cmp=`lte`、target=2、节奏=`weekly`，When 本周记录 3 次，Then 周期状态「已超额」并标红，连续周数归零。
- Given 配额 target=1，When 打卡一次，Then 卡片文案为「已完成 · 点一下撤销」，不出现「1 / 1 次」。

### FR-03 时段拆分（Slots）

**描述**：一天可拆为 2–4 个时段，各时段有名称与起止时刻，用于「早/中/晚」类习惯。

| 字段            | 取值                                          | 约束                                                     |
| ------------- | ------------------------------------------- | ------------------------------------------------------ |
| `key`         | `morning`/`noon`/`evening`/`night`/`custom` | 同一习惯内唯一                                                |
| `name`        | ≤4 字                                        | 默认「早/中/晚/夜」                                            |
| `from` / `to` | `HH:mm`                                     | `from < to`；不允许跨零点（跨零点请用「夜」到 23:59 + 次日单独时段，本期不支持跨日时段） |

**业务规则**：

- R3.1 时段与 `deadline` 互斥配置：同一习惯只能选「单一截止时刻」或「多时段」之一，避免两套时间语义打架。
- R3.2 时段内打卡：计入该时段，胶囊显示实心 + 打卡时刻。
- R3.3 时段外打卡（补记）：**允许**，仍计入该时段配额，但标记「晚于时段」，并在详情页统计「准时率」时排除。
- R3.4 时段与配额组合：`perSlot=true` 时每时段独立配额；`perSlot=false` 时时段仅作为「建议执行时间」，配额在整日累计。
- R3.5 时段判定只在「日」周期内有效；`weekly`/`monthly` 型习惯**禁止**配置时段（否则周期语义断裂），界面隐藏该项。

**验收标准**

- Given 时段 早 06:00–09:00 / 中 11:00–13:00 / 晚 18:00–21:00，perSlot=true，每段 1 杯，When 08:10 打卡，Then 「早」实心并显示 08:10，其余两段空心，今日进度 1/3。
- Given 同上，When 10:30 补记「早」，Then 该段计入 1 杯并标「晚于时段」，今日进度 2/3。
- Given 节奏=`weekly`，When 打开表单，Then 「时段」区块不可见（或置灰并说明仅日型可用）。

### FR-04 计划日与弹性出现（Policy.appear）

**描述**：决定「配额型习惯哪几天出现在待办」。

| 取值            | 行为                                  | 适用            |
| ------------- | ----------------------------------- | ------------- |
| `elastic`（默认） | 本周期未达成前，每天都出现；一旦达成，当天剩余时间折叠为「本周已完成」 | 每周 N 次、每月 N 次 |
| `scheduled`   | 只在用户指定的星期/日期出现；未达成的周期不额外补位          | 指定星期、每月某日     |

**业务规则**：

- R4.1 `weekly`/`monthly` 默认 `elastic`；`weekdays`/`monthlyDay` 强制 `scheduled`（节奏本身已含日期）。
- R4.2 弹性出现必须在今日页**分组呈现**：「今日待办」「本周还差」「已达成（折叠）」，避免弹性型习惯挤占日型习惯的视觉优先级。
- R4.3 已达成后再次打卡必须允许（用户可能超额），但需二次确认样式（长按/点「+」），防止误触把已完成状态改回未完成。
- R4.4 周/月最后一天且未达配额时，卡片必须显示「本周期还差 N 次 · 今天最后一天」，不显示「已无法达成」这类负面文案。


**验收标准**

- Given 节奏=`weekly`、perWeek=3、弹性出现，When 周一至周三各打卡 1 次，Then 周四起该习惯进入「已达成」折叠区，今日待办不再占位。
- Given 同上，When 周三时仅打卡 2 次，Then 周四仍在「今日待办」并显示「还差 1 次 · 还剩 4 天（含今天）」。
- Given 节奏=`weekdays`、days=[1,3,5]，When 周二，Then 不出现在任何分组（不占位、不显示空行）。

### FR-05 打卡交互形态

**描述**：按「配额 × 周期」自动选择控件，禁止同一张卡出现两个语义相同的主按钮。

| 场景            | 控件                          | 说明                       |
| ------------- | --------------------------- | ------------------------ |
| 次数型、周期目标=1    | 通栏开关按钮                      | 点一次完成，再点撤销（沿用现有单次卡）      |
| 次数型、单日目标 2–6  | 圆点组 + 「x / N」               | 点第 i 个=记到 i 次（沿用现有 pips） |
| 次数型、单日目标 >6   | 步进器 − / ＋                   | 沿用现有                     |
| 次数型、周期目标（周/月） | 主按钮「完成一次」+ 周期进度条            | 主按钮常驻，不做 toggle；撤销独立     |
| 数值型           | 数字输入 + 快捷值（+1 / +250 / 自定义） | 提交后显示「今日 x / 目标 y 单位」    |
| 戒除型、额度=0      | 横条「今天守住了 / 今天失守了」           | 沿用现有 v103 口径（不数失败次数）     |
| 戒除型、额度>0      | 主按钮「又记一次」+ 「本周 x / 上限 y」    | 超额时标红并显示「已超额」            |
| 时段型           | 时段胶囊 × N + 当日合计             | 点击胶囊即打卡该时段               |

**业务规则**：

- R5.1 单次打卡必须 ≤2 次点击（含撤销）；不得引入「打开详情 → 选时段 → 保存」这类三步路径。
- R5.2 打卡成功必须有反馈：动效（尊重 `prefers-reduced-motion`）+ 数字/进度即时变化；反馈文案使用事实口径（「本周 2/3」），禁止评判式文案（「太棒了」「又没做到」）。
- R5.3 撤销只回退最近一次操作，不清空整天/整周；撤销后不播放奖励动效。
- R5.4 所有可点控件必须满足 44×44 触控区，且进入 `@media (pointer: coarse)` 的命中区扩充规则。

**验收标准**

- Given 周期型卡片，When 点击主按钮一次，Then 进度从 1/3 变 2/3，且不出现「已完成」字样（未达配额）。
- Given 已打卡 2 次，When 点击撤销，Then 变 1/3；再点撤销变 0/3，不出现负数。
- Given 用户在系统设置里开启「减少动效」，When 打卡，Then 只发生数值变化与震动（如有），不放大元素。

### FR-06 补卡（Backfill）

**描述**：允许补记最近 N 天（默认 7，可设 0/3/7/30），用于忘记打卡。

**业务规则**：

- R6.1 补卡入口必须藏在「详情页日期格长按」或「卡片···菜单」，主界面不出现「补卡」按钮，避免降低即时记录的诚实度。
- R6.2 补卡记录必须带 `backfilled=true` 与补卡时间戳，日历格显示角标「补」。
- R6.3 补卡计入「完成量」与「周期达成」，但**不计入**「准时率」；连续天数按补卡日是否达标正常计算（用户可自行选择不使用该功能）。
- R6.4 禁止补记未来日期；禁止补记习惯创建日之前；禁止补记已暂停区间。
- R6.5 补卡上限按习惯配置，达到上限后入口置灰并说明「本次已补 3 天，上限 3 天」。

**验收标准**

- Given 补卡窗口 7 天，When 补记 3 天前，Then 成功且该日格带「补」角标，今日页不出现额外提示。
- Given 补卡窗口 0 天，When 打开日期格，Then 无补卡入口。
- Given 习惯创建于 11-10，When 尝试补记 11-08，Then 拒绝并提示「创建日之前不能补记」。

### FR-07 跳过、暂停与休息日

| 机制  | 字段                       | 规则                                     |
| --- | ------------------------ | -------------------------------------- |
| 跳过  | `events.k='skip'`，周期内计数  | 每周期上限默认 1 次（可 0–3）；跳过不破连续、不计失败；用满后按钮置灰 |
| 暂停  | `policy.pausedFrom/To`   | 暂停区间不出现在待办、不参与统计分母、不破连续；恢复后从当前周期继续     |
| 休息日 | `policy.restDays[]`（0–6） | 指定星期不要求完成；该日不计入配额分母，日历显示斜纹             |

**业务规则**：

- R7.1 跳过与休息日的区别必须在界面文案上说清：跳过=「本周我不想做这一次」，休息日=「这一天我从来不做」。
- R7.2 暂停最长 90 天，超过需重新设置；暂停期间**禁止**打卡（入口隐藏），避免产生「暂停中还要求达标」的矛盾。
- R7.3 跳过次数用尽后，再次尝试必须提示「本周跳过次数已用完（1/1）」，不静默失败。

**验收标准**

- Given 每周跳过上限 1 次，When 本周已跳过 1 次后再点跳过，Then 提示已用完且不产生记录。
- Given 休息日=[0,6]，When 周六，Then 该习惯不出现在待办、不计入本周分母，日历格斜纹。
- Given 暂停区间 11-10 至 11-14，When 11-12 打卡，Then 打卡入口不可用；11-15 恢复后连续周期数未中断。

### FR-08 周期视图与进度

**描述**：每张周期型习惯卡必须能在不跳页的情况下回答「本周/本月还差多少、还剩几天」。

**业务规则**：

- R8.1 卡片必须包含：周期进度（x / N + 单位）、剩余天数（`还剩 N 天（含今天）`）、周期点阵（周型 7 格 / 月型按周分行）。
- R8.2 点阵三态：实心=已完成贡献、空心=应做未做、斜纹=不需要做（休息日/未到周期）。
- R8.3 详情页必须提供三种视图：本周（点阵 + 每日量）、本月（日历热力）、历史（按周期列表：达成/未达成/跳过/暂停）。
- R8.4 详情页统计必须标注口径：「周期达成率 = 达成周期数 ÷ 应达成周期数，不含暂停与休息日」。
- R8.5 详情页可以显示「按当前节奏，还能达成 / 已无法达成」，但**禁止**在今日页显示负面结论。

**验收标准**

- Given 周型习惯 2/3，When 查看卡片，Then 同时可见「2/3」「还差 1 次」「还剩 4 天」与 7 格点阵。
- Given 查看详情页本月视图，When 某日为休息日，Then 该格为斜纹且不计入分母，图例可解释斜纹含义。
- Given 周期已结束且未达成，When 打开历史列表，Then 显示「未达成 2/3」而非「失败」。

### FR-09 判定与统计口径（核心）

**描述**：引入三层判定，禁止任何视图跨层取数。

| 函数（语义）           | 输入    | 输出                                | 使用方                    |
| ---------------- | ----- | --------------------------------- | ---------------------- |
| `dueOn(h,d)`     | 习惯、日期 | 布尔：今天是否需要做（含暂停/休息日/已达成折叠判定）       | 今日页待办、通知、日历「应做」标记      |
| `met(h,d)`       | 习惯、日期 | 布尔：**日粒度**达标                      | 日历热力、连续天数（日型）、月报「达标天数」 |
| `acc(h,d)`       | 习惯、日期 | 0–1 或数值：当日贡献度                     | 月度小结、详情页每日量            |
| `metPeriod(h,d)` | 习惯、日期 | {done, target, ratio, met}：所在周期累计 | 周期进度、周期达成率、连续周期数       |

**业务规则**：

- R9.1 `met(h,d)` 语义收窄：仅回答「这一天本身是否满足当日要求」。对周期型习惯，`met` 返回「当天有贡献且当日要求已满足」，**不得**用周期累计结果反推某一天达标。
- R9.2 周期型习惯的「连续」必须按周期计（连续 N 周 / N 月），界面单位随之改变（「周」「月」），禁止显示「连续 12 天」。
- R9.3 今日页 KPI 必须拆两个，不混算：
  - 「今日待办 x/y」分母 = 今日 `dueOn=true` 的日型与命中日型习惯（周期型未达成时计入，已达成折叠时不计入）；
  - 「本周节奏」= 周期型习惯达成数 ÷ 周期型习惯总数。
- R9.4 日历热力：日型按 `met` 着色；周期型按「当日贡献」着浅色（`acc>0`），周期结束后若该周期达成，则整段回填实心；休息日/暂停/不需要日一律斜纹。
- R9.5 月报「达标总天数」只统计日型；周期型单独一行「周期达成 x/y」，不得相加。
- R9.6 所有比率的分母必须排除：暂停日、休息日、习惯创建日之前、归档之后。
- R9.7 同一习惯在三处视图的达标结论必须一致；任何新增统计必须调用上表四个函数，禁止内联重写判定。

**验收标准**

- Given 周型习惯本周已 3/3，When 查看今日 KPI，Then 该习惯不计入「今日待办」分母，且「本周节奏」计为达成。
- Given 月报页面，When 存在 2 个周期型习惯，Then 「达标总天数」不含其周期内的打卡天数，另起一行显示「周期达成 4/6」。
- Given 同一习惯在今日页显示「本周 3/3 已完成」，When 打开日历与月报，Then 结论一致（均为该周达成），无一处显示「未达标」。

### FR-10 新建/编辑表单（三步）

**描述**：把现有 18 个字段的长表单重构为三步，主路径只暴露必要决策。

| 步骤     | 内容                                              | 默认值        |
| ------ | ----------------------------------------------- | ---------- |
| ① 做什么  | 图标、名称、类型（养成/戒除）                                 | 图标 ✅、类型 养成 |
| ② 多久一次 | 节奏卡片（6 选 1）+ 配额（次数/数值 + 单位 + 方向）+ 可选「时段」/「截止时刻」 | 每天 + 1 次   |
| ③ 怎么记  | 打卡形态（自动推荐，可微调）、提醒（沿用现有通知区）、休息日/跳过额度、颜色、备注       | 沿用现有       |

**业务规则**：

- R10.1 每一步必须有「实时预览句」，用自然语言回述配置，例：「每周 3 次 · 每次 1 次 · 本周还差 3 次 · 还剩 5 天」。
- R10.2 必须提供 6 个内置预设，一键填好第②③步：每周 3 次运动、每天 8 杯水（分 3 时段）、每 3 天浇花、每月 1 次理发、每周最多 2 次奶茶、21 天挑战。
- R10.3 高级项（跳过额度、补卡窗口、暂停）默认折叠，展开后才写入字段；未展开时使用默认值。
- R10.4 保存前必须做冲突校验：`weekdays` 未选任何星期、`weekly` 配额 >7、`interval` 锚点晚于今天、时段不连续或重叠、数值型单位为空 → 阻止保存并定位到具体字段。
- R10.5 编辑已有习惯时，若修改了节奏或配额，必须在保存前提示：「修改只影响本周及以后，历史按原规则保留」，二次确认后才保存。
- R10.6 常驻习惯的表单**禁止**出现节奏卡片与时段区块（保持现有字段，仅名称/目标/颜色可改）。

**验收标准**

- Given 新建流程，When 只填名称并保存，Then 默认「每天 1 次」，与现有行为一致。
- Given 选择「每周 3 次」，When 配额填 2（每次 2 次），Then 预览显示「每周 3 天 · 每天 2 次 · 周目标 6 次」，且周期进度按 6 计。
- Given 编辑节奏从「每天」改「每周 3 次」，When 点保存，Then 弹出历史不回算提示，取消则不保存。
- Given 常驻习惯，When 打开编辑，Then 不显示节奏/时段区块。

### FR-11 管理列表与排序

**业务规则**：

- R11.1 每行必须显示周期徽标：`每天` / `每周 3 次` / `每 3 天` / `每月 1 次` / `周一三五`，替代现有含义模糊的「每天 × 1 次」。
- R11.2 新增排序维度「按周期达成率」，与现有排序并列；低频习惯的达成率必须用「周期达成率」而非「天达成率」，避免「每周 1 次」永远垫底。
- R11.3 归档/删除规则不变；周期型习惯归档后历史保留，恢复后从当前周期继续，不回算归档期间。

**验收标准**

- Given 「每月 1 次」的习惯，When 查看列表，Then 徽标显示「每月 1 次」而非「每天 × 1 次」。
- Given 排序选择「达成率」，When 列表渲染，Then 周期型按周期达成率参与排序，不与日型混用同一分母。

### FR-12 与现有模块的边界（硬约束）

| 模块                                       | 约束                                                 |
| ---------------------------------------- | -------------------------------------------------- |
| 常驻卡（`PINNED_IDS`、`optional=false`、戒烟、用药） | **禁止**读取 `sched`/`quota`/`slots`/`policy`；渲染与数据零改动 |
| 提醒系统                                     | 只消费 `dueOn`，不反向推导节奏；`notifyFreq` 语义保持「提醒频率」        |
| 今日页常驻区                                   | 结构与样式不动；新内容只进入「小习惯」区                               |
| 日历/月报/统计                                 | 只允许按 FR-09 分层取数，禁止内联判定                             |
| 导出/导入/备份修复                               | 新字段必须进入白名单兜底；未知顶层键保持原样带过                           |

**验收标准**

- Given 打开今日页，When 对比改动前后的常驻卡 DOM 结构与数据字段，Then 完全一致。
- Given 导出 JSON 再导入，Then `sched`/`quota`/`slots`/`policy` 完整保留，周期进度一致。

## 九、业务流程与状态流转

### 9.1 打卡记录状态机（单条记录）

| 当前状态 | 触发事件   | 新状态                    | 允许操作 |
| ---- | ------ | ---------------------- | ---- |
| 未记录  | 打卡     | 已记录（`source=manual`）   | 撤销   |
| 未记录  | 补卡     | 已记录（`source=backfill`） | 撤销   |
| 已记录  | 撤销     | 未记录                    | —    |
| 未记录  | 跳过     | 已跳过（本周期计数 +1）          | 取消跳过 |
| 已跳过  | 取消跳过   | 未记录                    | —    |
| 任意   | 进入暂停区间 | 冻结（不可打卡）               | 结束暂停 |

### 9.2 周期状态机

```
未开始 ──周期首日──▶ 进行中 ──达成──▶ 已达成（当日折叠）
                        │
                        ├──周期末日未达成──▶ 未达成（结算，计入分母）
                        ├──跳过用尽/休息日──▶ 不计入（分母排除）
                        └──暂停覆盖整周期──▶ 已暂停（完全排除）
```

规则：

- 周期一旦结算即为只读，后续补卡只影响记录展示，**不改变**已结算周期的达成结论（宽限期除外，本期默认 0）。
- 周期结算时间以本地时间 23:59:59 为准，不设服务端定时任务。

### 9.3 规则变更流程

```
用户改节奏/配额 → 提示历史不回算 → 确认 → 写入 sched/quota + effectiveFrom=今天
                                        → 当前未结算周期按新规则重算（可选，默认重算）
                                        → 已结算周期读 schedHistory 快照
```

### 10.1 新增字段（语义契约）

> 本节只定义字段语义与边界，不规定实现方式。所有字段仅在**非常驻**习惯上生效。

| 字段             | 类型     | 说明                                                                                          | 缺省                                                   |                   |                      |
| -------------- | ------ | ------------------------------------------------------------------------------------------- | ---------------------------------------------------- | ----------------- | -------------------- |

| `schedHistory` | array  | `[{from:'YYYY-MM-DD', sched, quota}]`，规则变更快照                                                | `[]`                                                 |                   |                      |
| `quota`        | object | \`{kind:'count'                                                                             | 'value', target, unit, cmp:'gte'                     | 'lte', perSlot}\` | 由 `target`/`unit` 映射 |
| `slots`        | array  | `[{key,name,from,to}]`，2–4 项                                                                | `[]`                                                 |                   |                      |

| `ev`（事件扩展）     | —      | 打卡事件增加 `slot`、`value`（数值型）、`backfilled`、`source`                                            | —                                                    |                   |                      |

### 10.2 老数据映射（只读映射，不改写原字段）

| 现有形态                         | 映射结果                                             | 说明            |
| ---------------------------- | ------------------------------------------------ | ------------- |
| `target=1`、`type=build`      | `sched=daily`、`quota={count,1}`                  | 行为完全不变        |
| `target=9`、`unit=杯`          | `sched=daily`、`quota={count,9}`                  | 行为不变          |
| `type=quit`、`slipMode=once`  | `sched=daily`、`quota={count,0,cmp:lte}`          | 「每天守住」= 日上限 0 |

| 有 `deadline`                 | 保留 `deadline`，不生成 `slots`                        | 二者互斥          |
| `notifyFreq=weekly/monthly`  | **不映射**为节奏                                       | 明确解耦：它只影响提醒   |

## 十二、异常处理清单

| #  | 场景                       | 期望处理                         |
| -- | ------------------------ | ---------------------------- |
| 1  | 节奏=`weekdays` 但未选任何星期    | 阻止保存，高亮该控件，提示「至少选一天」         |

| 3  | `intervalDays` 设为 0 或负数  | 阻止保存                         |
| 4  | `anchorDate` 晚于今天        | 允许保存但提示「周期从 X 月 X 日开始」，之前不出现 |
| 5  | `monthDay=31` 遇 2 月      | 收敛到 28/29 日，并在表单提示           |
| 6  | 时段起止重叠或 `from>=to`       | 阻止保存，提示具体哪两段冲突               |
| 7  | 时段数 >4 或 <2              | 阻止保存                         |
| 8  | 数值型单位为空                  | 阻止保存，提示「请填单位」                |
| 9  | 数值输入非数字或为负               | 拒绝提交，保留原值                    |
| 10 | 记录数为 0 时点撤销              | 按钮置灰，不产生负数                   |
| 11 | 同一秒内多端各打一次卡              | 合并后取较大值（次数型）；数值型累加；不产生重复条目   |
| 12 | 跨零点打卡（23:59 点，00:01 同步）  | 按设备本地日归属；冲突时以较早时间戳为准并留痕      |
| 13 | 周期最后一天 23:59 打卡          | 计入本周期，不因网络延迟落入下一周期（以记录时间戳判定） |
| 14 | 修改节奏后查看历史                | 历史按 `schedHistory` 快照展示，不回算  |
| 15 | 删除习惯后周期视图                | 仅在归档区可见历史；永久删除则一并移除          |
| 16 | 归档期间跨越多个周期               | 归档期间不计入分母，不产生「未达成」记录         |
| 17 | 暂停期间打开详情                 | 显示「已暂停至 X 月 X 日」，打卡入口隐藏      |
| 18 | 跳过次数用尽                   | 提示已用完，不静默失败                  |
| 19 | 导入旧备份（无新字段）              | 全部按 `daily` 映射，功能正常          |
| 20 | 导入新备份到旧版本                | 旧版本忽略未知字段（兜底带过），不报错、不丢数据     |
| 21 | 习惯数量 >200 或历史 >5 年       | 周期视图分页/懒加载，首屏不扫描全量           |
| 22 | 时区/夏令时切换                 | 以本地日切；不因时区跳变产生重复或缺失日         |
| 23 | `perSlot=true` 但某时段当日未配置 | 该时段不计入分母，界面灰显                |
| 24 | 戒除型配 `cmp=gte`（语义矛盾）     | 表单禁止该组合，自动切回 `lte`           |

### 15.2 原型说明
