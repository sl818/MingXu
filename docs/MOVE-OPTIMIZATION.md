## 一、背景

运动模块是 v176 之后重做的一块，v179～v184 又连续改了六轮：

| 版本 | 做了什么 |
| --- | --- |
| v176 | 运动模块重做：模式库、目标档、频率、通知开关 |
| v178 | 单日多次（每天做几次）、每周选日也能设次数 |
| v179 | 模式精简为 7 种、「记录字段」改名「运动数据记录」、补数据表单动态化 |
| v181 | 打卡状态机：打卡 → 记数据 → 才放行下一次，可「跳过不记录」 |
| v182 | （已被 v183 撤回）允许编辑时切换模式 + 历史记录归档 |
| v183 | **编辑时锁定运动类型**，只能新建 |

改动很密，测试却只覆盖了「建完就断言存档」这一条路径 —— **没有「保存后重开再断言」的往返**。结果就是陛下这次实测点出来的五个问题里，有两个（勾选回显、距离放错位置）从来没被测到过。

本轮的目标：**把反馈逐条改到位，同时把测试从「单点断言」升级成「真人走一遍」**，让下一轮同类问题在我这边就能发现，不用等陛下点。

## 二、五条修复需求

### 需求 1 · 「补数据」按钮改名 + 填红

**现象**（陛下截图 1）
运动完成后，那次运动还没补详细数据时，卡片上出现一个「补数据」按钮。按钮是普通灰色文字，看不出"这件事还没了结"，名字也短，用户不知道点进去是干嘛的。

**期望**

| 项 | 值 |
| --- | --- |
| 按钮文案 | `补数据` → **补充运动后详细数据** |
| 底色 | **#DC2626**（红底白字） |
| 出现时机 | 不变：只在存在「跳过了记录数据」的那次时才出现 |

**改法**
- `moveSportCardHtml(` 里生成按钮那段，把文案换掉，并给这个按钮加一个专用类（红色实心底）。
- 「今天已完成」那行的 `note` 也要跟着改口径：现在写的是「有 N 次跳过了记录数据，点『补数据』补上」，文案要换成新名字。
- 颜色按项目配色约定：红色留给「需要特别注意 / 尚未了结」的事，蓝色留给「开启一件事」。这个按钮正是"还没做完"，用红合适。

**涉及文件**：`index.html`（`moveSportCardHtml`）· `assets/app.css`（按钮样式）

**验收**
- 跳过一次后，卡片上出现红底白字的「补充运动后详细数据」。
- 填完数据后，这个按钮消失。
- 底色确实是 #DC2626。

### 需求 2 · 今日任务记录显示完整字段

**现象**（陛下截图 2、3、4、5）
今日任务记录里，每条记录只显示**值**，不显示**字段名**：

```
50 分钟
52 分钟 · 3 公里 · 配速 5:20 · 33 步/分 · 126 bpm · 765 …
```

三个毛病：①看不出「50 分钟」是时长还是次数；②字段被容器宽度截断；③用户填了哪些字段完全看不出来。

**期望格式**（陛下原话）

```
第一次运动：                    11-25 19:56   修改  删除
· 运动时长（分钟）50 分钟
· 距离（公里）3 公里
· 配速 5:20
第二次运动：                    11-25 19:56   修改  删除
· 运动时长（分钟）36 分钟
· 距离（公里）5.2 公里
· 配速 6:25
```

| 项 | 规则 |
| --- | --- |
| 组标题 | `第一次运动：` / `第二次运动：` 独占一行，带中文冒号 |
| 字段行 | 每行一个字段，行首 `· ` |
| 字段内容 | `字段名（单位）` + 空格 + `值`（值自带单位，如 3 公里、50 分钟）；没有单位的字段直接 `字段名 值`（配速、心率区间） |
| 数值 | 原样显示，不四舍五入（3 公里、5.2 公里、6:25 都保持原值） |
| 组标题何时出现 | **只有这个运动本身设了「每天 2 次及以上」才出现**；每天 1 次的直接列 `· 字段` 行，不加标题 |
| 跳过没记的那次 | 仍显示 `未记录详细数据` |
| 截断 | 不再截断 |

**改法**
- 新增一个「把一条记录渲染成多行字段」的辅助函数，字段名与单位取自模式库里的定义（弹窗里的那个标签就是它），值取记录里存的数。
- 序号按该运动设置里的「每个执行日做几次」判断：大于 1 才编号，编号按当天记录的先后顺序排。
- `moveRecListModal(` 的行结构要改成「组标题行 + 字段行若干」，日期时间与「修改 / 删除」按钮放在组标题行右侧。
- `moveRecSummary(` 是卡片与统计页在用的摘要函数，**不要动它**（卡片上要短），只有「今日任务记录」这个弹窗用新的详细渲染。

**涉及文件**：`index.html`（`moveRecListModal`）· `assets/app.css`（字段行排版）

**验收**
- 单日多次的运动，今日任务记录里出现「第一次运动：」「第二次运动：」两组，每组下面每个字段一行。
- 每天 1 次的运动没有组标题，直接是 `· 字段名（单位）值`。
- 填了 7 项的记录，7 项都列出来，不截断。
- 跳过的记录显示「未记录详细数据」。

### 需求 3 · 运动数据记录的勾选回显 bug

**现象**（陛下截图 6、7、8）
两种表现，同一个根因：

1. 把「运动数据记录」**全部取消勾选** → 保存修改 → 重新打开编辑 → **又全被勾上了**
2. 新建跳绳只勾了「总次数 / 心率 / 热量消耗」→ 点编辑 → **五项全被勾上**

**根因（已定位）**
勾选状态存在运动实例的 `fields` 数组里，**保存是对的**（存档里确实只存了勾上的那几项）。错在回显：渲染复选框时用的是「没有被明确取消就算勾上」这种写法，于是**根本没出现在存档里的字段（值是 undefined）也被当成了勾中**。

新建时之所以正常，是因为新建路径会先把该模式的所有字段置为勾上，再由用户取消 —— 取消的那几项会显式记成 false。编辑路径没有这一步，undefined 落进了「算勾上」的分支。

**改法**
- 勾选状态改为**严格判断**：只有明确记为 true 的才算勾上。
- 初始化勾选状态时，先把这个模式的全部字段置为「未勾」，再把存档里勾上的那几项置为「已勾」。
- 顺带把保存侧也校一遍：存档里的 `fields` 必须是数组，空数组要原样保留（不能被默认值覆盖回全选）。

**涉及文件**：`index.html`（`bindMoveSportForm(` 里的勾选状态初始化与复选框渲染）

**验收**
- 全部取消 → 保存 → 重开编辑 → 仍然全部未勾。
- 只勾 3 项 → 保存 → 重开编辑 → 仍然只有那 3 项勾着。
- 新建时的默认（默认全勾，用户自己取消）行为不变。

### 需求 4 · 每日步数的「距离」归位

**现象**（陛下截图 9、10、11）
- 点「记录步数」打卡时，弹窗里**混进了「距离（米）」** —— 这是错的。
- 每日步数的运动数据记录配置里只有「距离（米）」这一项 —— 这是**对的**，要保留。

**根因**
弹窗的字段是按运动勾选的项统一生成的，而每日步数勾选的项就是「距离（米）」。但距离属于**运动后数据**（达标之后才记），不该出现在打卡表单里。

**期望**
| 场景 | 弹窗里的字段 |
| --- | --- |
| 打卡（「记录步数」） | 日期、任务完成时间、步数（步）、记录方式 —— **没有距离** |
| 达标后（「补充运动数据」） | 只有「距离（米）」 |

**改法**
- 每日步数的**打卡表单**只渲染步数与记录方式，不渲染运动后数据的字段。
- **达标后**的补充弹窗（`mode='after'`）照旧渲染勾选的字段 —— 每日步数就是「距离（米）」。

**涉及文件**：`index.html`（记录弹窗的字段渲染）

**验收**
- 打卡弹窗里没有「距离（米）」。
- 达标后弹的补充弹窗里只有「距离（米）」，且距离写进**同一条**步数记录（不另开记录，否则统计里的次数会翻倍）。

### 需求 5 · 每日步数的「记录方式」建好后锁定

**现象**（陛下截图 1 的红框）
每日步数的「记录方式」（手动输入今日步数 / 每次记录固定步数）在**编辑时还能来回切换**。

**期望**
| 场景 | 表现 |
| --- | --- |
| 新建 | 两个选项随便选 |
| 编辑 | **不可切换**：当前那种保持高亮，另一项灰掉不可点；误点了给提示 |
| 固定步数的**数值** | 仍可改（锁的是"选哪一种"，不是"每次加多少步"） |

**改法**
- 与 v183 的运动类型锁定**同一套手法**：选项加禁止态样式、弹窗里给一条带锁的提示、点击时弹一句 toast 说明，不做切换。
- 提示文案：`🔒 记录方式建好后不能修改。如果想换一种，请新建一个运动。`

**涉及文件**：`index.html`（`bindMoveSportForm(` 的记录方式选项）· `assets/app.css`

**验收**
- 编辑每日步数时，只有当前记录方式可选，另一项灰掉。
- 点灰掉的那项，出现提示且不发生切换。
- 固定步数的数字输入框仍可修改。

## 四、全面回归测试方案

### 4.1 原则

1. **只用界面点击**，模拟真实用户 —— 不直接改 `state`（除了专门造老数据、脏数据那种场景）。
2. **既看界面显示，也核对底层数据**：两边不能打架。存档对了界面错、界面对了存档错，都算失败。
3. **补上往返路径**：保存 → 重开 → 再断言。这一轮所有涉及「设置项」的用例都必须走一遍往返。
4. 发现的新 bug **一并修掉**，不只记录；修完重跑确认。

## 七、容易踩的坑（留给下一个人）

1. **补数据弹窗没有步数输入框** —— 按表单重建记录会把原记录的步数冲成 0，表现为「达标后又变回没达标」。补数据必须以原记录为基底，没填的项保留原值。
2. **`let` 是块级作用域** —— 把变量声明写在 `if` 块里、块外又要用，会报 `xxx is not defined`。
3. **字段全靠 JS 拼串** —— 判断某个 class 是否死代码要搜字面量，不能凭印象。
4. **覆盖 `#main` / `#nav` 的宽高边距必须带 id** —— 类选择器打不过 id 选择器。
5. **`var(--bad)` 不能用在小字上** —— 对比度不够，改用正文色。
6. **PHP 里 `$todayDate->setTime()` 会改对象本身** —— 循环里必须先 `clone`。
7. **星期常量前后端都是 0=周日** —— 写 `Number(x) || 1` 会把周日 0 当成周一。
8. **改动 CSS/JS/HTML 后必须 bump SW**，否则线上用户拿到的是新 HTML 配旧缓存。
9. **新增顶层字段要改三处**：`normalizeState` / `mergeStates` / `repairBackup`（第三处漏了直接删数据）。
