# 设计参考库

> 2026-11-18 / 19 两天调研的素材池，来源两个：**Trackie**（在线竞品，免费主机上的 PHP 站）
> 和 **Yuvomi**（Docker 自托管的家庭规划器，MIT，2.4k stars）。
>
> 每条写四件事：**谁这么做 · 具体怎么做 · 我们现状 · 改造成本**。
> 用途是给大改版备料，不是待办清单——要动手时从第 9 节挑，别一次全上。

---

## 0. 改版前必读：这些是我们已经做对的

改版最容易犯的错是「把好的也一起改掉」。下面是明序目前站得住的几条，**改版时要保住**：

| 已有设计 | 为什么是对的 |
| --- | --- |
| 6 套皮肤 × 明暗，颜色只走 CSS 变量 | 换主题不改 DOM，也不会有元素漏改颜色 |
| 命令面板（`Ctrl/⌘ + K`）认得出命令也认得出搜索词 | 认不出就退回搜索，不会报错——这条容错设计比多数产品好 |
| 打卡支持「补记」：日历点过去的日子直接记 | 承认人会忘，比「只能记今天」诚实 |
| 乐观锁 + `mergeStates` 自动合并，冲突不弹框 | 用户不会因为「数据冲突」这种词被打断 |
| 今日页常驻四卡（用药/喝水/运动/呼吸）固定在最上 | 高频操作零跳转，这是 Trackie 和 Yuvomi 都没做到的 |
| 折叠型信息（本月概览、算法说明、编辑页参数）都默认收起 | 一屏只留该看的 |
| 打印样式、`pointer: coarse` 触屏补偿、对比度审计 | 三个容易被忽略的细节，我们都有 |

## 1. 表单与录入

### 1.1 渐进披露：必填只有标题，其余折进「更多信息」

- **来源**：Yuvomi · 新建任务弹窗
- **怎么做**：弹窗里只平铺 4 项（标题、截止日期、优先级、分类），另外 9 项——开始日期、重要日期、积分、标签、状态、可见性、文档、重复、轮换和提醒——收在一个折叠区里，
  折叠区的标题下**直接列出里面有什么**（一行小字），用户不点开也知道有什么，不会漏功能。
- **我们现状**：任务表单、清债表单都是全展开，字段一多就要滚。
- **成本**：低（一个折叠容器 + 一行说明）。**性价比最高的一条。**

### 1.2 主按钮跟着页面走

- **来源**：Yuvomi · 右上角固定位置
- **怎么做**：同一位置，健康概览页是「+ 记录」、断食页是「+ 开始断食」、任务页是「+ 任务」、饮食页是「+ 餐食」。
- **我们现状**：各页固定文案（「新建」「新建任务」）。
- **成本**：极低（改字符串）。收益是用户每次都知道点下去会发生什么。

### 1.3 自然语言输入

- **来源**：Trackie · 今天页输入框
- **怎么做**：`placeholder` 直接写「Type a date or time in plain words (tomorrow 6pm, next Fri)」，支持 `!high` / `!low` 标优先级。
- **我们现状**：命令面板已支持「新任务 交报告 明天」，能力更强，但**发现性差**——输入框的 `placeholder` 没提示这些写法。
- **成本**：极低（改 `placeholder` + 提示文案）。**我们功能已有，只是没告诉用户。**

### 1.4 「我更早开始了」

- **来源**：Trackie · 断食页
- **怎么做**：计时器旁一个按钮，一键把开始时间往前拨（承认用户忘了点开始）。再加「+ 添加已完成的断食」，允许完全手动补录一次历史。
- **我们现状**：有「补记」模式，但入口在日历页选日期，今日页没有「我现在才想起来」的直达路径。
- **成本**：低（今日页加一个入口，指向已有的补记逻辑）。

## 2. 列表与看板

### 2.1 同一批数据的三视图：列表 / 看板 / 历史记录

- **来源**：Yuvomi · 任务页
- **怎么做**：顶部分段控件切三种视图。看板回答「现在有什么」，历史回答「过去做了什么」。
- **我们现状**：只有看板。已完成的清理掉之后就查不到了（只能进导出文件）。
- **成本**：中（新增一个只读视图，不动数据）。**「历史」这个缺口比「列表视图」更值得补。**

### 2.2 卡片上直接「标记完成」

- **来源**：Yuvomi · 任务卡片右下角
- **怎么做**：卡片上直接一个「✓ 标记完成」，不用打开详情、不用拖拽。
- **我们现状**：要么拖到「已完成」列，要么右键编辑。
- **成本**：低。**移动端没有拖拽时，这是唯一顺畅的路径。**

### 2.3 统一清单「UP NEXT」

- **来源**：Trackie · 今天页
- **怎么做**：习惯和待办混在同一个列表里，每行标类型（`Habit · Daily` / `Todo`），按「接下来做什么」排序，顶部一句「9 left · next up: 30-min workout」。
- **我们现状**：习惯是卡片、待办是列表，两块分开。分开适合「管理」，混排适合「执行」。
- **成本**：中（新增一个聚合视图，不新增数据）。可以做「接下来 3 件」的窄条，只展示不编辑。

### 2.4 三态打卡：完毕 / 失败 / 跳过 ⭐

- **来源**：Trackie · 习惯卡片
- **怎么做**：每个习惯三个按钮，`✓ 完毕`、`✗ 失败`、`⏩ 跳过`。跳过 = 豁免一天，**不打断连续记录**。
- **我们现状**：只有「达标 / 未达标」两态。生病、出差时用户只能造假装完成，或者断签。
- **成本**：**高，是这份文档里唯一动数据模型的一条**。要动 `met` / `dayStats` / `rateOver` / `habitDayAcc` 四处口径，
  同步 `algoModal` 镜像，还要保证 ICS 与提醒过滤一致。
- **价值判断**：这是唯一一条改变「记录真实性」的设计，也是唯一需要认真权衡代价的一条。**建议单独立项，不和别的改动混。**

## 3. 空状态

### 3.1 空态写「下一步做什么」，不是「暂无数据」

- **来源**：Yuvomi · 各模块
- **怎么做**：「还没有完成的断食 / 开始个人断食计时器并查看历史记录」+ 一个主按钮。
- **我们现状**：不少空态只有前半句（「还没有数据」）。

### 3.2 空态顺手讲清「功能之间的关系」

- **来源**：Yuvomi · 饮食页
- **原话**：「本周还没有任何计划 / 按天和按餐次安排早餐、午餐、晚餐和小食。**计划排好后，购物清单一步就能补好。**」
- 第三行在解释这个功能和另一个功能的联动，等于教了一个用法。
- **成本**：纯文案，零风险，覆盖面最广。

## 4. 数据可视化

### 4.1 年度热图（26 周 × 7 天）

- **来源**：Trackie · 分析页
- **怎么做**：GitHub 贡献图那种格子，深浅表示当天完成度，下面有「较少 → 更多」图例。
- **我们现状**：日历只有月视图。月视图回答「这个月怎么样」，热图回答「**我坚持了多久**」。
- **成本**：低到中（纯展示，数据已有，一个网格即可）。

### 4.2 顶部一句话摘要

- **来源**：Trackie · 今天页 Hero
- **怎么做**：「9 left · next up: 30-min workout」，右边一个 `0/9 DONE` 圆环。
- **我们现状**：Hero 是「晚上好 · 完成 6/17 项」，没有「下一件是什么」。
- **成本**：极低（一句字符串）。**打开就知道该干嘛，比「完成了多少」更有用。**

### 4.3 综合评分（谨慎）

- **来源**：Trackie · 分析页「Trackie 评分：需要改进」
- **怎么做**：把多个维度压成一个分 + 一句话评价。
- **我们现状**：没有综合分，只有单个指标。
- **判断**：评分容易变成「被系统评判」，和「明晰诸事」的克制调性有张力。**如果要，只做「状态描述」不做「打分」。**

## 5. 信息架构

### 5.1 子项少用 tab，分类多用侧栏

- **来源**：Yuvomi 三个模块用了两种导航，不是随手定的：

| 模块 | 子项数 | 导航 |
| --- | --- | --- |
| 健康 | 9 | 左侧二级侧栏（分类浏览，每类是一个独立数据类型） |
| 厨房 | 4 | 顶部 tab |
| 预算 | 7 | 顶部 tab（同一批数据的多种视图） |

- **规律**：**分类浏览用侧栏，同数据多视图用 tab。**
- **我们现状**：清债 6 子页用顶部 tab（正确）；体重、习惯是单页（正确）。**这块我们本来就是对的，改版别乱动。**

### 5.2 域 → 类型两层

- **来源**：Yuvomi 侧栏：计划 / 家庭 / 人员 / 预算 四个域，下挂 19 个模块；健康域内再用二级分类。
- **我们现状**：12 个页面扁平列出，手机上 4 个高频 +「更多」抽屉。
- **判断**：12 页扁平是我们能承受的上限，**再加页面就必须分组**。分组时参考「域 → 类型」，不要学它的 4 组 19 项。

### 5.3 每块卡片都留「全部」入口

- **来源**：Yuvomi · 概览页（生日 / 家庭 / 便签，每张卡片右上角一个「全部」）
- **我们现状**：部分有（「更多」），不统一。
- **成本**：低。作用是让概览页的卡片都能通向完整页面，不会「看得到进不去」。

## 6. 游戏化（折扣采纳）

- **来源**：Trackie · 进步页（30 个徽章 + 等级 + 经验值）
- **它怎么做**：徽章网格，锁定灰、解锁彩色；等级进度条「1 级 · 初级 · 0/100 经验」。
- **判断**：**徽章可以学，等级和经验不要**。
- 我们的调性是「明晰、有序、克制」，加等级会把工具变成游戏，稀释品牌。
- **建议形态**：只做「里程碑」静态列表（连续 30 天、累计 1000 次打卡、连续 100 天记账），不解锁动画、不给经验值、不排名。
- **成本**：中（要新增记录 + 判定逻辑）。

## 7. 动效观察（只记能确认的）

调研过程中能确认存在的动效，不做推测：

| 来源 | 动效 | 说明 |
| --- | --- | --- |
| Yuvomi | View Transitions API | 代码里引了视图过渡模块（View Transitions），切页面时有形变过渡 |
| Yuvomi | 弹窗缩放淡入 | 打开新建任务时，背景模糊 + 弹窗从中心轻微放大 |
| Trackie | 进度环 | 今日完成度圆环，数值变化时环形填充 |
| 我们 | 圆环 / 折叠 / 主题切换过渡 | 已有，改版时保住 |

> 动效这块**没有逐帧分析**，只记录了一眼能看到的。真要抄动效，建议直接看它们的 CSS 变量与 `transition` 声明，比截图准。

## 8. 明确不抄

| 不抄 | 原因 |
| --- | --- |
| 家庭多成员（切换、分配、角色权限） | 我们是单用户自托管，加这套等于重做数据模型 |
| 20 个模块的广度 | 定位不同。他们「一个 App 替代一堆订阅」，我们「一个工具做深六件事」 |
| Vite / 构建步骤 | 我们的部署模型是「把文件传上去」，加构建会让门槛翻倍。**但要记住：Yuvomi 从 v2.93 起放弃了无构建，说明这条路在 2 万行附近会到极限** |
| 第三方集成（Spotify / GitHub / Steam） | 与「数据只在你自己服务器」冲突 |
| 综合评分与等级系统 | 与克制调性冲突，见 6 节 |
| 壁挂平板模式 | 场景太窄（家庭共享屏），我们没有这类用户 |

## 9. 建议的落地顺序（真要改时按这个来）

| 优先 | 做什么 | 成本 | 依赖 |
| --- | --- | --- | --- |
| 1 | 表单「更多信息」折叠（1.1）+ 主按钮跟随页面（1.2） | 半天 | 无 |
| 2 | 空态统一加「下一步」（3.1 / 3.2） | 2 小时 | 无 |
| 3 | 顶部一句话摘要（4.2）+ 卡片「完成」按钮（2.2） | 半天 | 无 |
| 4 | 年度热图（4.1） | 半天 | 无 |
| 5 | 任务「历史记录」视图（2.1） | 半天 | 无 |
| 6 | 统一清单「接下来 3 件」（2.3） | 1 天 | 无 |
| 7 | **三态打卡（2.4）** | 2–3 天 | 独立立项，动数据模型 |

前五项加起来约两天，全部是前端展示层，不碰数据。第 7 项单独排期。

## 10. 改版风险清单

1. **CSS 已经外移到 `assets/app.css`（v116）**，里面是 6 层叠加、166 组跨层重复选择器。改版时**从最后一层改**，别新建第 7 层。
2. **12 个页面是信息架构上限**，再加功能优先考虑「并入现有页面」。
3. **新增顶层字段必须同步三处**：`normalizeState` / `mergeStates` / `repairBackup`（漏第三处会删用户数据）。
4. **改判定必须同步 `algoModal`**，它是考核算法的镜像，不同步等于文档在撒谎。
5. **改完 bump `service-worker.js` 的 `CACHE`**，否则老用户看不到新版。
6. **发布包现在是 26 个文件**（含 `assets/app.css` 与三张图标），漏传 `app.css` 就是整站没样式。

## 11. Trackie 的视觉语言（目测自截图，未取精确色值）

它的布局并不复杂，但「看起来舒服」来自几条一致的规矩。改版如果要走暖色路线，这套可以直接参考：

| 规矩 | 具体做法 | 我们的现状 |
| --- | --- | --- |
| **底色分层，不靠阴影** | 页面底是暖米色，卡片纯白，靠明度差分层；卡片几乎没有投影，只有少数卡带 1px 细边 | 我们用 `--line` 描边 + 轻阴影，偏冷 |
| **大圆角** | 卡片 16–20px，按钮全圆角（胶囊） | 我们是 12–14px + 小圆角按钮 |
| **彩色卡片＝模块身份** | 天气卡黄底、分析卡绿底、集成卡红底——每张卡的颜色就是它是什么的说明，不用再放标题 | 我们所有卡同色，靠标题和小图标区分 |
| **主行动按钮最高饱和** | 「+ 新习惯」是饱和红色胶囊，页面里只有它这么重 | 我们的主按钮用皮肤主色，克制但不够抓眼 |
| **导航选中态＝浅底 + 主题色字** | 当前页是淡粉底 + 红字，不做左侧色条 | 我们用左侧色条 + 加粗 |
| **列表项带彩色字母徽标** | 「应这样做」每行一个圆形字母（A/B/C/D/E），每行不同色，快速扫读靠颜色不靠文字 | 我们没有这类"行首标记" |
| **分组可折叠侧栏** | 计划 / 生活 / 爱好 / 进步四组，每组标题可点开收起 | 我们扁平 12 项，手机走「更多」抽屉 |
| **顶部横幅做一次性提示** | 红底白字横条置顶，可关闭 | 我们的提醒横幅是浅底描边，轻一些 |

**一个值得注意的取舍**：它的信息密度其实很高（一屏 12 个模块入口 + 6 张卡），但因为「同色系不同明度 + 大圆角 + 卡片间 16–20px 留白」，读起来不挤。**密度高不等于拥挤，关键在分块和留白**。

**动效部分暂缺**：这站的 CSS 拿不到——它对非浏览器请求有 JS 挑战（aes 脚本），`curl` 和内置浏览器都过不去；
Chrome 扩展通道当次断开。等能拿到样式表再补这一节，包括 `transition` 时长、缓动曲线、hover / active 状态、
以及它是否用了 View Transitions。
