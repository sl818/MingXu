这一批修了什么（第 1 批：上限 5 + 三条必须修）

  1. 改前的坏处：输入框 max="12" 让浏览器原生校验在提交之前就把表单拦了 —— 点「保存设置」毫无反应（上图左边：红色气泡 + 没有 toast + 值仍是 13）。代码里的 clamp 根本走不到。
  2. 改后：表单加 novalidate、去掉输入框的 max，保存时统一收敛到 1–5 组，并靠重绘把值回填到输入框，同时用 toast 说清「已按上限改为 5 组」。填 6 时提示行立刻给出「上限 5 组，保存后按 5 组存」。
  3. 补点不再撞车：以前把组数从 3 改成 4，第 4 个提醒时间会被补成 21:00（和已有的重复）→ 后端推送去重把后一条吃掉，那一组永远收不到提醒。现在按位置逐位填：3→4 = 07:00 / 13:00 / 21:00 / 11:40，两两不同。
  4. 保存提醒不再丢时间点：改了组数但没点「保存设置」就直接保存提醒时，现在会按界面上实际存在的框收全，并把组数一起同步。
  5. 手填重复时刻（两个框都填 07:00）：保存时自动错开成 07:00 / 14:00 / 21:00，toast 提示「重复的时间已自动错开」。
  6. 上限 5：前端 11 处 + 后端 3 处全部收到 BREATHE_MAX_GROUPS / LB_BREATHE_MAX_GROUPS（以前散在 14 个地方）。每组循环次数上限仍是 8，没动。
