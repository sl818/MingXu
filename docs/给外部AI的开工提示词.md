## 提示词正文（从下一行开始整段复制）

请先完整阅读并遵守以下开工约定，再开始我的任务。这一份约定是你接手本项目唯一需要的背景，不要凭通用经验跳过其中任何一步。

### 一、开工第一步（必做，不可跳过）
1. 读 `docs/CHANGE-MAP.md`（改动地图）。它按功能列出「改哪个函数 / 同步哪几处 / 跑哪个测试」，是在两万行前端里定位的入口。
2. 读该文件文末「地图修改日志」的最后 3 条，看有没有别的会话刚改过我要动的那一节。撞上了先停下来问我，别重复改或互相覆盖。
3. 地图是导航不是圣旨：里面写的函数名、口径要在代码里核实一遍再用。它本身可能过期（历史上就查出过整节缺失和 4 个死函数名）。

### 二、项目基本面（别按标准 Web 项目想象）
- 单文件前端 `index.html`（约 2 万行，全部在一个 IIFE 里），无构建、无 CDN、无框架；样式在 `assets/app.css` 与 `assets/theme-v2.css`；后端是 PHP 8 + MySQL，主逻辑在 `api.php`，接口在 `api/`；离线缓存由 `service-worker.js` 控制。
- 数据模型是全量快照：`boards.data` 一列存整份 state，前端 `mergeStates` 负责合并，`base_rev` 做乐观锁。没有按业务分表，别去假设有运动记录表、随笔表之类的东西。
- 主题只有一套、浅色/深色两态，改主题动 `assets/theme-v2.css`。旧的六皮肤机制已下线，别照旧文档加皮肤。
- 测试在 `e2e/` 目录，约 170 个脚本；本机 Python 解释器是 `C:/Users/slgzs/.workbuddy/binaries/python/envs/default/Scripts/python`（默认 python 没有 playwright），跑测试要分批，串成一条会超时。

### 三、改动硬规则（都是踩过坑的地方，务必照做）
- 新增顶层字段必须同时改三处：`normalizeState` / `mergeStates` / `repairBackup`。漏第三处会直接删数据。
- 提醒与日历过滤三处口径要一致：前端 `buildICS` / `api/ics.php` / `api/schedule.php`。
- 每次改 CSS / JS / HTML 都要递增 `service-worker.js` 的缓存版本号；版本号四处同步：前端资源查询串、`APP_VERSION` 常量、SW 的 `CACHE`、SW 的 `VER`。递增前先看最近的 git 提交，有并行改动就顺延版本号，别覆盖别人的提交。
- 全仓换行是 LF；脚本读写文件用 `io.open(path, encoding='utf-8', newline='')`，别把仍是混合换行的老脚本统一掉。
- 线上只有一个测试账号，邮箱和密码都是 test@sl00.top。别再问账号、别新建测试号。登录会踢掉其他会话，用完记得登出。
- 视图层是 JS 拼字符串 + 全量重绘，事件走 `data-act` 委托。改一处常要同步别处，动手前先看地图里的同步点清单。

### 四、改完登记（必做）
- 只要这次改动触及地图里已有的条目（函数名改名或删除、新增模块或顶层字段、合并口径变化、新增测试脚本、主题或导航口径变化），当场更新地图对应行，并在文末「地图修改日志」追加一行（日期 / 版本 / 改了哪几节 / 摘要 / 发起方）。日志只追加，不改旧行。
- 改完跑一次文档锚点检查（`e2e/check-doc-anchors.py`），确认没有把锚点改坏。
- 纯问答和只读分析不用登记；只改文档也要登记。

### 五、沟通与产物
- 称呼我「陛下」。所有界面可见文字一律中文（包括你发给我的进度说明），英文只出现在代码、命令、文件名和原始日志里。
- 不做预览稿，直接改代码落地；测试数据不要删，我要登录看。
- 只出一个 `Todo-update.zip`，不生成版本回退包，包准备好了先别上传，我自己传。
- 页面改版要出改前/改后可切换的对比网页，让我能直接看到改了什么。

### 六、明确不做（别反复建议）
- 安卓 App / 微信小程序；引入 Vue 或 React 等框架；ESM 模块化；Web Components / Shadow DOM；全量数据库分表重构。这些都已评估过，与当前规模不匹配。

确认你已读完并理解以上约定，然后再开始我下面的任务。
