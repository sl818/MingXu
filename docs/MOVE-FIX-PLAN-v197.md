## 批次 A：统计口径统一（不动状态机）

### A1 · 问题 5 + 问题 6：把「步数」从「运动后数据」里摘出来

**口径重新定义（这是这一版最重要的一条）**：

| 数据 | 来源 | 跳过时算不算 |
| --- | --- | --- |
| 次数、运动天数 | 打卡 | **算** |
| 步数 | 打卡时记的 | **算**（步数不是运动后数据） |
| 时长 / 距离 / 心率 / 热量 / 配速 / 步频… | 运动后数据表单 | **不算**（没填就是没有） |
| 「有详细数据」 | — | 不算（跳过就是没填） |

v181 当初定的「跳过只计次数」在运动后数据这一层继续有效；要修的是**步数被误当成运动后数据一起剔掉**。

**改法**：
1. `moveStatAgg`：累计步数（`o.steps`）的累加挪到「跳过」判断**之前** —— 步数是打卡数据，跳过也照计。
2. `moveStatAgg`：`byDay` 里的 `n`（有运动的天数）保持含跳过（当天确实动了）；
   但 `byDay.score`（热力图用的当天运动量）要把跳过那次的步数也按「100 步 ≈ 1 分钟」折算计入，
   否则会出现「有运动的天数 +1、热力图那天却是灰的」。
3. 「按运动模式」的距离/时长仍排除跳过（不动，v191 已对齐）。
4. 文案：「有运动的天数」改成「**有记录的天数**」（更准确：当天有记录就算）。

**涉及**：`moveStatAgg`、`moveStatsHtml`（KPI 文案）。
**验收**：造一条「步数已打卡但被跳过」的记录 → KPI 累计步数含它、步数档位含它、热力图那天有颜色、时长/距离不含它。

### A2 · P2-4：「全部」范围的起点按当前模式算

**现象**：切到「跑步」+ 时间选「全部」，跨度仍按**全局**最早记录（可能是步数半年前记的）算，
于是按周分成 6 个点、前 5 周全是 0，图上一大半空着。

**改法**：`moveStatBounds` 增加"模式"参数；`all` 的起点取**当前模式自己的最早记录**，
没有记录时才回落到全局最早。

**涉及**：`moveStatBounds`（及其调用处：`moveStatsHtml`）。
**验收**：切跑步 + 全部 → 趋势图不再有前段空白段。

### A3 · P2-5：最近记录的时间与卡片日志对齐

**改法**：统计区「最近记录」的时间改用 `moveRecHM`（与卡片「今日任务记录」同一取法），
不再用 `hour` 拼 `:00`。

**涉及**：`moveStatsHtml`（最近记录区块）。
**验收**：一条 19:24 的记录，两处显示都是 19:24。

### A4 · P2-6：距离的「补过即锁定」提到日粒度

**现象**：今天补录了距离（12,061 米）→ 删掉那条记录 → 距离归零、达标归零，
而且**还能再补录一次距离**，「补过即锁定」的承诺只在记录还在时成立。

**改法（甲方案）**：把锁从"记录上有 distM"提升到"**这一天**已经补过距离"。

1. 运动实例上新增字段 `distLocked`（`{ 'YYYY-MM-DD': true }`），补录距离成功时写入当天。
2. 补填/补数据弹窗：当天已锁 → 显示「今天已经补过距离了，不能再补第二次」，
   并给出「查看那条记录」的入口。
3. 删除带距离的记录时**不清这个锁**，同时提示「今天的运动后数据已经记过了，删记录不会撤销这次补录」。

**⚠ 新增字段必须同步登记**：按项目硬规则，顶层字段要同步 `normalizeState` / `mergeStates` / `repairBackup`；
本次是**运动实例内部字段**，实际要登记的是 `normalizeMoveSport`（白名单）+ `mergeStates` 的运动合并分支 +
`repairBackup` 的运动修复分支 —— **三处都要加，漏一处会静默丢数据**。
（审查时还发现 `normalizeModule` 是"第四处登记点"且没有未知键兜底，这一版顺带把它加上兜底：
未登记的键原样带过，以后加字段不会再被洗掉。）

**涉及**：`normalizeMoveSport`、`mergeStates`、`repairBackup`、`normalizeModule`、
`saveMoveRecordForm`、`moveRecordModal`（文案）、`moveDelRecord`（提示）。
**验收**：补录距离 → 删记录 → 再补录 → 弹窗提示已锁；重新加载页面后锁仍在。

### A5 · 小文案：达标时不说「还差 0 步」

**改法**：KPI「距 X 步还差」在已达标时改成「**已达标**」。

**涉及**：`moveStatsHtml`（步数 KPI）。

## 批次 B：判定与文案

### B1 · P2-3：卡片上的「目标」要跟实际判定一致

**先纠正一个误解**（审查子代理说"只数记录条数"不准确）：非步数运动的判定从 v178 起就是
「**每天几次**」（`freqN` / `perDay`），这是陛下当时拍过的（"用户设了每天 3 次也只要打一次卡就算完成，形同虚设"）。
真正的问题是：**目标档里的距离/时长（`tIdx` / `tVal`）从来没参与过判定，却显示在卡片上**，
于是卡片写着「目标 5 公里」，实际要求的是「每天 2 次」。

**改法（建议）**：卡片上那一格改成显示**真正的判定依据**「每天 2 次」/「每周选日运动」；
距离/时长目标不再出现在卡片上（它本来就是"每次距离"的参考值，编辑弹窗里仍然能看到和改）。

**不选"按距离判定"的原因**：那会推翻 v178「每天几次」的设定；两个目标同时生效会变成"每天 2 次且每次 5 公里"，
比现在更难懂。

**涉及**：`moveSportCardHtml`（`.mv-ft` 那几格）、`moveTargetOf` / `moveProgress`（取值口径）。
**风险**：卡片文案会变，陛下若不喜欢这版措辞可以改成「每天 2 次（参考：每次 ≥5 公里）」。

### B2 · P2-1：「＋添加记录」要说清属于哪个运动

**现象**：运动页页头的「＋ 添加记录」用来手动补录一次忘了打的卡，但它建记录时**不写是哪个运动实例**，
系统只能按运动类型猜归属。用户只有一种该类型运动时其实正常；**同时有两个「跑步」时归属就不确定**，
删掉那个实例后记录还会变成没人管的孤儿。

**改法**：这个表单加一个「**属于哪个运动**」下拉（列出全部运动实例，标注类型与图标），
保存时把 `sportId` 一起写上。默认值按当前选中的运动类型预选。

**涉及**：`moveRecordModal`（add 分支的表单）、`saveMoveRecordForm`。
**验收**：补录一条跑步记录 → 它出现在跑步卡片里、能改能删；两个跑步实例时能指定是哪一个。

## 批次 C：状态机（问题 4）

### C1：待填记录不能再"消失"

**现象**：打卡后弹出的「补充运动后数据」只有两个出口（跳过 / 更新这条），但**ESC 和点遮罩都能关掉它**；
关掉后这条记录留在 `pending` 状态，而 `movePendingRec` 只查今天、补数据列表只列 `skipped` ——
**跨天之后这条记录再没有任何入口**，同时统计把它算成了「有详细数据」。

**改法（三处一起）**：

1. **不许直接关**：待填弹窗加一个标记；`closeModal` 检测到它就不关，改为提示
   「先填数据，或选『跳过不记录』」（ESC 与遮罩点击都走 `closeModal`，一处就能堵住两条路）。
2. **历史 pending 有入口**：补数据列表从"只列 skipped"扩成"列 **skipped + pending**"，
   范围从近 7 天放宽到近 30 天；标题改成「待处理」。
3. **统计里单列**：记录质量区块加一格「**待处理（pending）**」；
   `moveStatAgg` 的 `realN`（有详细数据）排除 pending；pending 的那一次不计入时长/距离，
   但**步数照计**（同 A1）。

**涉及**：`closeModal`、`moveSkippedRecs`（扩成"未处理记录"）、`moveRecordModal`、
`moveStatAgg`、`moveStatsHtml`（记录质量区块）。
**验收**：打卡 → ESC（关不掉，提示）→ 选跳过 → 状态干净；
故意让一条 pending 跨天 → 次日补数据列表里能看到它。
