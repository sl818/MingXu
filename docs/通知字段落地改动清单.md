## 4. 存储决策

- 模板存 `app_settings` 的 `notify_tpl_<uid>` KV 行，**零数据库迁移**；
  依据：`api/push.php` L300–303 的注释、`db/schema.sql` L78–82 的 KV 表结构。
- **不进 `state`**，因此不碰 `seedState()` / `normalizeState()` / `mergeStates()` / `repairBackup()` 四处白名单，
  也不会被全量快照同步覆盖。
- 板块总控 `notifyBoards` 若最终进 `state`，才需要另走那四处（这是汇总文档第 11 节的方案 A，本次清单默认不含）。
  即使进 `state`，模块类板块也**只存渠道不存启用**——启用派生自 v209 的 `state.modules.<key>.on` /
  `state.modulePrefs.meds.on`，避免两处可写互相覆盖。

## 7. 影响评估与风险

| 风险 | 处理 |
| --- | --- |
| 去重键被改坏，老记录全部重发 | 事件只**加**可选字段，`日期|kind|id|time` 键原样不动 |
| 默认矩阵被模板改乱 | 模板只管文案，通道仍由 `notify_prefs_<uid>` 决定，两边不混 |
