# P0 · 喝水模块通知渠道：模块级路由未落地

> 优先级：**P0（以后必做）**　创建：2026-11-24　相关版本：v173
> 定位：这是一笔明确的技术债，UI 已经做了、推送没跟上。任何智能体接手本项目都应看到并安排重做。

## 一句话结论
喝水页（v173）已上线「通知渠道多选」（浏览器 / 企业微信群 / 邮件）的 UI 与数据存储，
但**实际推送仍未按喝水模块自己选的渠道路由**——企微/邮件仍走全局「用户级通知偏好」，
浏览器通知走前端 PWA。用户勾了某个渠道，不等于真的会从那个渠道收到。

## 现状：做了一半的
- **前端 UI 完整**：`waterNotifyHtml()` 渲染渠道三选（可多选），`saveWaterNotify()` 把
  `notifyChannels: ['browser','wecom','mail']` 存进 `state.modules.water`。
- **数据层完整**：`moduleDefaults` + `normalizeModule` 已收敛 `notifyChannels` 白名单，
  合并/导入/备份路径自动补齐。
- **提醒时间点完整**：`buildICS` / `api/ics.php` / `api/schedule.php` 三处已按 `notifyMode`
  生成多时间点（每次按杯数均分 / 每天固定 1–3 次），这部分与渠道无关、已对齐。

## 没做的部分（真正的债）
后端推送路由仍是「用户级 + kind 级」偏好，不是「模块级」：

- `api/push.php` 的 `lb_notify_defaults()` 只按 **kind** 给默认渠道，`habit` 类默认
  `['wecom'=>true,'mail'=>false]`；`lb_notify_prefs_load/save` 存的是**用户**对每个 kind
  的开关，跟具体哪个模块无关。
- `lb_push_tick_run` 的发送/去重按 `(user_id, slot_key, channel)`，渠道来自用户级偏好，
  **没有读 `state.modules.water.notifyChannels`**。
- 浏览器通知（browser）是前端 PWA 路径（Notification / 推送订阅），PHP 后端无法直接发；
  目前喝水勾了「浏览器」只是存了值，实际触发仍依赖现有的前端通知能力。

## 造成的后果
- 用户在喝水页勾了「邮件」，但账号全局没开「习惯类邮件提醒」时，喝水不会单独发邮件。
- 想做到「喝水走邮件、运动走企微」这种**模块级差异化**，做不到。
- UI 承诺与真实行为不一致，属于体验债 + 信任债。

## 为什么当时没做（缘由）
- v173 落地重点在「喝水页改版 + 内联设置 + 数据统计 + 提醒频率双模式」，渠道多选是顺带落地的 UI/存储。
- 模块级渠道路由要动 `api/push.php` 的推送 tick：让每条喝水提醒在发送前读
  `state.modules.water.notifyChannels` 决定走哪些 sender，涉及去重 key 与 notify prefs 的
  叠加语义（模块级 vs 用户级谁优先），风险面大，不宜单次提交一并塞入。
- 浏览器通知的定时推送本质是「Web Push + 订阅管理」的独立能力，与现有「企微/邮件」
  服务端定时发送是两套机制，需要单独设计。

## 后续方向（重做时怎么做）
1. **模块级渠道覆盖用户级偏好**：喝水模块勾选的 `notifyChannels` 覆盖（或合并）用户级
   `habit` 偏好。建议语义：模块勾了某渠道 = 显式启用；未勾 = 回落到用户级偏好。
2. **推送 tick 读模块渠道**：`lb_push_tick_run` 生成/发送时，对 kind=habit 且 id 前缀
   `h_water` 的条目，读取 `state.modules.water.notifyChannels` 决定 wecom/mail 走哪些 sender。
3. **浏览器通知独立能力**：若要让「浏览器」渠道真正定时触发，需引入 Web Push
   （订阅 token + VAPID + 服务端推送），与企微/邮件并列成第三类 sender；这是独立项目，
   不建议塞进本次改版。
4. 完成后补 `verify-*` 断言：同一账号下「喝水只勾邮件」时，到点只发邮件、不发企微。

## 相关位置（锚点，不写行号）
- 数据层：`index.html` 的 `moduleDefaults` / `normalizeModule`（`notifyChannels`）
- 前端 UI：`index.html` 的 `waterNotifyHtml` / `saveWaterNotify` / `bindWaterPage`
- 渠道偏好：`api/push.php` 的 `lb_notify_defaults` / `lb_notify_prefs_load/save` / `lb_push_tick_run`
- 提醒生成：`api/schedule.php` 的 `lb_schedule_day`（喝水多时间点）、`api/ics.php` 的 `lb_water_slots`
