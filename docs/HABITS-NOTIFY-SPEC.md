## 1. 两个 BUG

- 保持类未定位，怀疑编辑链路整体覆盖冲掉 target。**开工第一步写复现测试定位，禁止未定位先修。**

### BUG-② interval 点完成后卡片消失（第 9 条）
- 根因明确：v221 `todayVisible` 只给 weekly 做了达成折叠，interval 漏了 → `habitDueOn=false` 被过滤。
- 目标语义（陛下原话）：始终显示在今日页；当天完成仍可撤销；过了当天不在本轮要求窗口 → 打卡条两个按钮禁用、显示「未到打卡时间」。

## 2. 通知体系（与 sched 联动）

渠道：参考运动模块 `notifyOn`/`channels`（推送/邮件/看板亮灯）搬进习惯表单，未配置渠道给检测提示。

| 节奏 | 通知行为 |
|---|---|
| 每天 × 单次 | 单时间，每日推送 |
| 每天 × 多次 | 当日 N 次打卡 → **N 个通知时间**；**纯提醒，不做打卡截止节点**（口径已锁） |
| 每周固定几天 × 单次 | 按选中每一天推送；旧「每周几」单选下拉退役 |
| 每周固定几天 × 多次 | **每个选中日各配各的时间**（口径已锁：3 天 × 3 次 = 9 个独立时间） |
| 每周 N 次（弹性） | 不做单独通知，只进每日日报 + 「还有任务未完成」 |
| 每隔 N 天 × 单次 | 本轮要求日通知一次，当日时间自定义 |
| 每隔 N 天 × 多次 | 当天需要做时通知一次（不按次数拆） |

涉及后端：`api/push.php` / `api/schedule.php` / `api/ics.php` / `api/mailer.php` 四处提醒过滤必须同步（老规矩）。

## 3. 表单约束（戒除类可用组合收敛为四种）

保留：每天单次 / 每天多次 / 每周固定几天单次 / 每周固定几天多次。
禁止：每周 N 次 × 戒除、每隔 N 天 × 戒除、（选项）删除「每日单次 · 点了就是破了」。

## 5. 习惯通知接入通知路由的映射（2026-11-28 查证，开工时照此接线）

路由模型（docs/通知路由落地执行方案.md + api/push.php）：kind+source →  板块
（），过板块渠道矩阵、免打扰时段、12 场景文案模板、全局渠道检测；三链路 =
服务端 cron（企微/邮件）+ 浏览器本地提醒（remindItems）+ push_preview 排程（数据列表）。

习惯 2.0 的接入点：
1. **板块**： 板块（kind=habit 无 source）；不要为时间矩阵拆新板块行。
2. **三链路全接**：排程项进 push_preview；企微/邮件 cron 过板块过滤与免打扰；浏览器本地提醒套模板。
3. **文案**：复用  场景模板（9 变量），不为新节奏加场景。
4. **免打扰/小结**：自动生效；「每周 N 次不单独通知」的未完成项走 report 小结。
5. **习惯级渠道（notifyChannel）与板块渠道取交集**后发送——这是唯一需要新设计的点：
   板块矩阵是账号级总闸，习惯级是单习惯微调，两者都开才发。
6. **排程数据**：时间矩阵（每周几×每日独立时间）、interval 轮次通知，都是排程项的字段扩展，
   走 push_preview 扩版（v211 模式），不新增 state 顶层字段（方案 B：app_settings 偏好表）。
